1. 結論與證據等級

插件已有可驗證的功能及檢索改善；尚未證明一般 AI 任務成功率、審美、永久學習能力或帳單節省。 它透過檢索、需求約束、來源追蹤、按需載入與驗證回饋改善工作上下文，不改變模型權重。

證據結果支持的結論不支持的推論
程式／資料／MCP68／68 通過；0失敗、0略過已測行為與保護機制可運作所有情境無錯誤
瀏覽器操作50／50 流程通過，pageErrors空已測操作可完成全面無障礙或所有裝置認證
定向檢索對照舊版4／20，新版20／20三種已知缺陷修正有效通用命中率100%、AI能力提升80%
1,000份MD效能冷索引10.15秒，搜尋p95 5.89ms該語料與硬體的本機效能模型或網路回應速度

3. 程式與MCP完整項目

下列名稱直接取自 TAP；每項通過。涵蓋資料庫遷移隔離、CAS衝突、來源撤回、需求歷史、預算、範圍、版本、圖片、合併、政策、背景工作、可攜式啟動與工具協定。完整斷言與測試程式在 tests/，單一通過名稱不代表所有可能輸入均受覆蓋。

  • 1. Markdown parser ignores code links and completed examples; reads safe frontmatter
  • 2. scope scanner excludes vendor, own data, junction escapes and deduplicates hardlinks
  • 3. marking completed files never edits originals and becomes stale after a change
  • 4. deletion requires confirmed completed mark and handles inbound links in the same batch
  • 5. apply detects live inbound links introduced after proposal
  • 6. proposal and restore never overwrite concurrent edits
  • 7. batch rollback recovers earlier writes if a later write fails
  • 8. new references validate against planned files, protected files remain immutable
  • 9. audit identifies the five principles without treating code examples as commands
  • 10. context excludes pending deletion and memories respect scope, confirmation, expiry
  • 11. task completion requires evidence; changed goals invalidate previous verification
  • 12. visual references require supported bytes and preserve comparison scope
  • 13. merge guards every source version, including unchanged source files
  • 14. shared database serializes writers and releases lock after failure
  • 15. non-UTF8 Markdown is skipped without rewriting its bytes
  • 16. manual classification is versioned and never removes source protections
  • 17. HTTP local session checks token and origin, and round-trips Chinese payloads
  • 18. standalone md plugin negotiates MCP, lists scoped tools and opens its UI
  • 19. standalone insight plugin negotiates MCP, lists scoped tools and opens its UI
  • 20. portable Node md starts without PowerShell and supports the full tool profile
  • 21. portable Node insight starts without PowerShell and supports the full tool profile
  • 22. rounded numeric inode values never merge distinct files or hardlink groups
  • 23. migration snapshots legacy data, preserves the original and marks legacy confirmation for review
  • 24. warm scans read zero bodies and changed files alone are parsed
  • 25. temporarily unreadable subtrees preserve prior index and scope membership
  • 26. overlapping roots retain one document and removing a root retains other memberships
  • 27. completion display, filters and summary respect explicit completion withdrawal
  • 28. knowledge search requires query, bounds results and separates uncertain applicability
  • 29. knowledge CAS is atomic across connections; changed validated content needs new review
  • 30. knowledge trash and restoration preserve all revisions
  • 31. knowledge batch failures roll back prior writes; successful apply is idempotent and reversible
  • 32. retrieval ledger avoids repeated payloads and enforces a run byte budget
  • 33. source changes downgrade knowledge without erasing prior evidence
  • 34. FTS and short Chinese lookup return bounded section references; section reads reject stale source
  • 35. deletion detects newly introduced unindexed references and remains reversible
  • 36. failed compensation enters recoverable state and journal supports deterministic recovery
  • 37. task revisions, evidence and reports never fabricate a measured learning gain
  • 38. health and state avoid audit and full-content lists
  • 39. move repairs inbound and outbound Markdown links, preserves ID through rescans and restores
  • 40. section edits preserve BOM, CRLF and unrelated text
  • 41. similarity candidates remain evidence-based and become stale when a peer changes
  • 42. index jobs finish with observable counts and cancellation preserves previous entries
  • 43. automatic classification supports Chinese filenames and clearing overrides updates indexed lists
  • 44. long knowledge exceptions can be read fully with field pagination and a shared ledger
  • 45. domain packs preserve revisions and support bounded source reads
  • 46. compact MCP tools reveal only requested groups and preserve the full-host fallback
  • 47. v3 snapshots v2 and never writes back into the running old database
  • 48. ranking finds highly relevant late titles beyond the old first 120 candidates
  • 49. version ranges and scope filtering run before candidate limits
  • 50. retrieval generations invalidate sent-query caches and host vectors stay version bound
  • 51. research source changes invalidate dependent knowledge without losing original evidence
  • 52. task compilation preserves original request and old task revisions; context expires on revision
  • 53. read budgets apply to implicit runs, cross-scope reads, and reject unknown bypass arguments
  • 54. PNG crops use bounded workers, shared image budgets, and preserve source bytes
  • 55. visual recipes, regions and timelines check scope, coordinates, ordering and CAS
  • 56. pixel comparison records an actual measurement without asserting aesthetics
  • 57. merge rejects partial coverage and lost clauses; valid full coverage applies and restores
  • 58. router splitting and metadata edits preserve independent content, BOM and CRLF
  • 59. annotation and category failures roll back together
  • 60. autonomy policies block scope changes and quotas before changes and preserve undo
  • 61. persistent drafts survive another connection and reject stale saves
  • 62. selection snapshots report partial changes accurately and jobs never alter source files
  • 63. knowledge import produces candidates without overriding original identities
  • 64. tool definitions are unique, validate forbidden inputs, and keep UI reads outside AI budgets
  • 65. evaluation reports do not invent comparisons or significance
  • 66. default AI inventories fit the shared budget rather than returning UI-sized pages
  • 67. source removals invalidate referencing audit caches without forcing a full audit
  • 68. a mismatched run rejects knowledge mutations before saving

5. 檢索改進的定向對照

基準核心提交：574352abcc657cd87942891404ddcd4f47091160。1,579筆知識加1筆跨範圍對照；兩版使用相同語料、查詢與回傳上限6筆／12,288 bytes。舊版使用 KnowledgeStore 保留的v2搜尋分支，新版使用 RetrievalService；無embedding或外部LLM。本實驗為隔離演算法而繞過查詢預算，不代表正式MCP會繞過預算；正式預算路徑另有測試。

8. 相容性與限制

已驗證Windows啟動器、Node直連STDIO、兩插件各自啟動、MCP列工具／動態群組／完整模式fallback、真實MCP image block。未逐一完成所有Codex版本的市集安裝、macOS／Linux實機、Claude／Gemini／本地模型宿主認證。

適用具工具調用能力且宿主支援本機MCP的文字／程式模型；視覺任務另需圖片輸入及宿主轉送圖片。品牌名稱不是相容保證。普通網頁聊天不會自動取得本機工具。完整安裝方式與條件見使用手冊。

可證明的是資料被正確取用與管理，不是模型突然學會所有領域。視覺像素量測不能判定審美、動畫節奏或遊戲是否好玩。插件不內建模型API、雲端embedding、任意引擎執行器、永久清除或伺服器影片解碼。

9. 如何證明下一階段的AI實際成效

採固定模型與版本、相同提示詞／工具／預算／參考資料，對照「無插件」與「有插件」；使用未拿來調整規則的真實保留任務，隨機順序、多次執行並由不知道組別的審查者評分。至少涵蓋需求遵守、知識正確性與引用、程式驗收、視覺還原、修改次數、端到端耗時與宿主實際token。先公布每題結果與失敗案例，再依足夠樣本計算區間，避免只挑成功例子。

目前的合理判斷：功能與定向檢索改進已有證據；更廣泛的AI成果提升仍待上述實驗。 經驗資料的價值取決於來源品質、適用條件、失效機制與模型能否正確使用，保存越多不等於越聰明。
