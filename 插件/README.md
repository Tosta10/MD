# MD 管理台與理解工作台

本機插件第一版，適用 Windows 與 Node.js 24 以上。包含可直接開啟的管理介面、兩個獨立 Codex 插件、MCP 服務、原始碼及測試；不需要另設模型 API 金鑰。

## 直接開啟

雙擊 [開啟工作台.cmd](開啟工作台.cmd)，會開啟整合介面。也可分別開啟：

- [MD 管理台](md-manager/開啟工作台.cmd)：文件盤點、五原則檢查、整合提案、完成／待刪除標註、變更與還原。
- [理解工作台](insight-workbench/開啟工作台.cmd)：需求、限制、驗證、經驗與視覺比較。

啟動器優先使用 CODEX_NODE_PATH 或 Codex 提供的 Node，其次查找 PATH，不另外安裝系統軟體。介面只監聽 127.0.0.1；一般埠為 39471，單獨插件為 39472／39473，埠被占用時選擇其他本機埠。

第一次開啟時在「管理範圍」加入完整資料夾路徑，再掃描。個人 skill 資料夾需另外加入，不自行掃描所有磁碟或對話。可以選擇是否盤點套件文件；授權、受管來源與硬連結不經一般改寫／刪除工具處理。

## 在 Codex 使用

已建立專案本機 marketplace：網站資料夾的 `.agents/plugins/marketplace.json`，指向這兩個插件。插件資料夾也附有自己的本機 catalog。

1. 重新開啟／重新載入支援本機插件的 Codex 桌面應用，開啟本專案。
2. 在 Plugins Directory 選擇專案本機來源，安裝「MD 管理台」及「理解工作台」。本機插件不需要公開上架。
3. 在新對話提及插件，或使用 `$md-manager`、`$insight-workbench`。
4. 需要介面時請插件呼叫 `open_workbench`，即可取得和該 MCP 服務共用資料的本機網址。

目前已以官方 MCP SDK 客戶端驗證初始化、工具列表、角色邊界與介面啟動。建立 catalog 不等於已安裝到目前對話；應用內實際安裝、載入與權限仍由宿主管理，本次沒有修改個人 Codex 設定或重啟應用。

插件同時提供 portable `plugin.json`／`mcp.json` 與 Codex compatibility manifest。主要平台為 Windows 本機執行緒，不依賴 Codex 原生側邊欄擴充或雲端檔案存取。

## 完成與待刪除

選擇文件 →「標註」→ 填寫狀態、理由及完成／取代依據。可關聯取代文件，並確認是否已完成。

「待刪除」是保存在本機資料庫的旁註，不修改來源 MD，也不立即刪除。標註綁定 SHA-256；版本變動後需要重新確認。只有已完成、已確認、標註未過時，且沒有未處理的已索引入站引用，才能建立刪除方案。

「產生刪除方案」先顯示完整差異；確認套用才刪檔。原文保留在批次紀錄，可還原。還原遇到其他工作的新修改會停止，不覆蓋新內容。授權副本與舊日期本身都不是刪除理由。

## 整理與整合

「整理建議」提供五原則候選、精確重複及失效引用；規則命中不是語意判決。用途與觸發、流程拆分、依變更選測、明確授權及分工重疊，均需由 Codex 或使用者根據來源確認。

「標註」也可人工修正主要分類並記錄理由；分類綁定目前文件版本，不解除來源保護。選「自動判斷」可清除人工分類。

「整合文件」可選 2 至 8 份目前清單中的來源，並排查看、編輯目標完整內容，再預覽方案；來源檔案保留，可另外標為候選。沒有模型連線時不假裝自動完成語意合併。

Codex 可用 create_change_plan 建立最多 50 項 write／create／delete 的批次，同時處理附件及引用。整合方案用 sourceDocuments 鎖定所有來源版本。套用前重新核對雜湊及已索引引用；多個工作台的檔案套用／還原以本機鎖序列化。失敗時嘗試復原；進程中斷的 applying 批次可由還原流程處理。

引用檢查涵蓋目前已索引的本地 Markdown 連結；未加入目錄、被略過的大檔與外部系統中的引用不在保證範圍。單檔分析上限 2 MiB，非 UTF-8 來源保留原檔並回報。

## 理解與經驗

需求摘要保存目的、限制、交付物與完成條件；通過或未通過需有實際證據。需求或限制修正後，既有通過結果降為未驗證，避免舊驗收冒充新需求已完成。

經驗分為偏好、事實、決策、方法、失敗案例，保留來源、適用情境、專案、反例及失效日期。候選不會自動成為規則；Codex 檢索預設只使用符合範圍、已確認且未失效的內容。目前明確要求優先於舊經驗。

視覺參考支援 PNG／JPEG／WebP，上限每張 8 MiB；可比較兩張圖、保存選擇與理由，再整理為偏好候選。圖片觀察、審美判讀與程式影響分析由 Codex 配合 skill 及實際來源完成；後端不聲稱自行訓練模型、改變權重或讀取全部歷史對話。

## 資料位置

預設為使用者家目錄的 `.codex-md-workbenches/`，其中 `workbench.sqlite` 保存索引、標註、方案原文、需求與經驗，`assets/` 保存主動加入的圖片。兩個插件共用此位置，但各自只公開自己的工具。

設定 `CODEX_WORKBENCH_HOME` 可改資料目錄。MCP 與直接開啟工作台需使用相同設定才能看到相同資料。資料不儲存在插件安裝快取中；停用插件不會自動刪除資料。備份前關閉相關服務，再複製整個資料目錄，包含 SQLite 的 WAL／SHM（若存在）。

管理介面沒有直接模型 API 呼叫；Codex 透過工具讀取所選內容時，該內容會進入該次 Codex 工作脈絡。介面採本機來源與工作階段檢查，沒有遠端部署。

## 開發與驗證

在本目錄使用 `pnpm install --frozen-lockfile`、`pnpm build`、`pnpm test`。權威來源為 `src/`、`public/` 及兩個 `skills/`；`runtime/`、插件內 `public/` 與 manifest 由 build 同步，不直接維護兩份程式。

瀏覽器驗證在隔離資料夾執行，使用捆綁 Playwright 與 Edge；見 `tests/browser-check.mjs`。設定 WORKBENCH_PLAYWRIGHT_ROOT 為捆綁 node_modules 位置後執行；證據在 artifacts/，不修改使用者的來源文件。
