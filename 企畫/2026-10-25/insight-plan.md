# 理解工作台 v2 企畫書

## I-00｜目的與範圍

讓 AI 更準確掌握本次目的，按需取得適用的領域資料，把實際成果與錯誤轉成可維護經驗。成功應表現在更少需求偏差、可重現的解題成果、較低返工及可追溯的證據。

本產品提升的是資訊取得、上下文組裝、方法選擇及驗證流程；不直接修改基礎模型權重。領域知識是否能改善結果，需依模型、工具、資料版本及實際案例評估，不能以知識卡數量代表專業能力。

主要使用者是與 AI 協作的個人開發者及設計者。首階段為 Windows 本機、單使用者跨對話資料共用；多人權限、雲端同步與模型訓練另案。現況依據見 [I-01～I-08](references/baseline-and-sources.md#b-02理解工作台的實際缺口)。

## I-01｜設計原則

1. **短入口、可尋址內容**：skill 只說做什麼、何時用及必要邊界；大量資料保存成可搜尋產物，按 ID/版本詳讀。
2. **原子但不碎裂**：一張卡只承載一項能獨立判斷的主張或方法；相關卡共用領域包、案例與來源，不為每句話產生一份 MD。
3. **要求、事實、偏好、推論分開**：任務限制不能由過去推論偷偷改寫；偏好不能充當技術正確性的證據。
4. **先適用、再相關**：先排除錯範圍、錯平台、錯版本及失效內容，再搜尋。沒有適用結果就回報缺口。
5. **所有成果可維護**：AI 可以以穩定 ID 編輯、標記、合併、封存、移入回收區與還原；保留前後版本。

這符合技能按需載入、工具負責資料與受控動作的分工。[OpenAI Skills](https://developers.openai.com/plugins/concepts/skills)

## I-02｜現有不足與對應升級

| 現況 | 升級決策 | 完成判準 |
|---|---|---|
| 空查詢回傳所有有效經驗；無上限 | 搜尋必須帶 query/task，分層詳讀並限制 payload | 空查詢不回正文，沒有偷偷擴大範圍 |
| appliesWhen / notWhen 缺乏實際適用判斷 | 結構條件硬篩選＋文字條件明列不確定性 | 錯版本、被排除情境不進一般脈絡 |
| 改已確認內容仍可沿用舊證據 | revision、差異與實質修改後需複核 | 舊確認不冒充新內容已驗證 |
| UI 刪經驗即真刪，AI 無維護工具 | 共用變更服務＋回收區＋恢復 | UI 和 AI 都能以同樣規則維護 |
| 任務有驗收，但學習成果只有文字 | 來源/案例/環境/結果分離記錄 | 能區分「讀過」「用過」「通過驗證」 |
| 缺少領域、版本及依賴模型 | 薄領域包與來源/陷阱/範例索引 | 新領域可逐步補足，無需讀完整手冊 |

## I-03｜核心資訊結構

| 物件 | 放什麼 | 何時讀取 |
|---|---|---|
| 任務卡 | 目的、限制、交付物、完成條件、未知、假設 | 開始/續作/修正本次任務 |
| 知識卡 | 單一事實、偏好、決策、方法或陷阱及適用條件 | 搜尋命中且適用時 |
| 證據 | 來源版本、執行案例、環境、觀察與結果 | 判斷正確性或驗收時 |
| 領域包 | 適用任務、技術版本、來源索引、前置知識 | 進入該領域或有特定缺口時 |
| 產物 | 原始碼、圖片、互動原型、設計系統、測量資料 | 需要具體內容或視覺判斷時 |

固定欄位、狀態與示例見 [資料契約 C-01～C-03](references/contracts.md)。UI 顯示繁體中文標籤，工具回固定 enum 與 ID；技術識別字保留原文。相同資料不要另寫一份互相競爭的「AI 專用總結」。

## I-04｜把 Thariq 方法變成可選工具箱

原始方法與作者文章已對照於 [T-01](references/baseline-and-sources.md#t-01thariq-技巧如何轉成產品設計)。以下是本產品的延伸用法。

| 方法 | 何時選用 | 必須留下的最小產物 | 何時停止 |
|---|---|---|---|
| 盲點掃描 | 新領域、影響大、限制不清 | 未知項、後果、查證方式與優先序 | 關鍵未知已解決或已明確保留 |
| 多方案原型 | 偏好難以口述或有架構分岔 | 差異明確的少量候選、取捨與選擇 | 使用者已選定或差異不影響成果 |
| 反向訪談 | 答案會改變架構/交付物 | 已知答案、必要問題、暫定假設 | 足以完成本次範圍，避免反覆問已答事項 |
| 真實參考 | 美感、技術或互動標準不明 | 來源、版本、採用特徵及不可照搬部分 | 判斷標準已可操作 |
| 可視計畫 | 流程/依賴/互動需要對照 | 任務資料投影成流程或原型 | 可檢視的方案已足以決策 |
| 決策筆記 | 有重要取捨或偏離方案 | 決策、原因、替代方案、重訪條件 | 記下影響即可，不逐步寫流水帳 |
| 可審查說明 | 交付、交接或請人判斷 | 改了什麼、證據、缺口與下一步 | 能判斷是否完成 |
| 反向測驗 | 人類想理解改動或需驗證方法可重用 | 小型案例、答案/結果與分母 | 完成本次評估，不無限出題 |

不把八法寫成每次必走程序。人類理解測驗與 AI 應用能力測試分開；測驗通過不替代產品功能驗收。原始八法見 [Finding your unknowns](https://claude.com/resources/articles/a-field-guide-to-claude-fable-finding-your-unknowns)。

「精簡提示、豐富產物、精簡 skill」在本企畫中表示：使用者只需描述本次目標；產物內容可很完整，但有摘要、ID、章節及版本供按需查閱；skill 保留方法選擇和真實 gotchas。不是把所有厚產物塞進模型上下文。

## I-05｜不同領域的專業能力如何提升

流程為：辨識任務領域與環境 → 找出必要知識缺口 → 取得合適第一方資料/專案來源 → 用代表案例實作 → 核對結果 → 保存有條件的經驗 → 以新案例檢查遷移。

| 領域 | 需要的來源/產物 | 可觀察的驗證 | 不足時如何回報 |
|---|---|---|---|
| 程式/API | 官方版本文件、型別、專案來源、最小範例 | 真實輸入輸出、相容性與受影響行為 | 版本未知、未執行或工具不可用 |
| UI/視覺 | 作品參考、設計系統、畫面及互動狀態 | 閱讀層級、操作成功、窄版/縮放、使用者選擇 | 主觀偏好待確認，不虛構美感分數 |
| 遊戲/引擎 | 引擎版本、場景/資產結構、效能 trace | 可重現場景、執行結果、幀時間與玩家回饋 | 好玩與否需測玩，不以程式完成推定 |
| 資料/研究 | 原始資料、單位、方法與第一手論據 | 可重算結果、抽樣/統計條件、反例 | 來源或樣本不足，結論只限觀察範圍 |
| 新的專業領域 | 領域包及必要專家來源 | 代表案例與外部審閱 | 檢索到內容不等於具備專家資格 |

領域包不收整本百科；先保存能改變決策的來源、版本陷阱、反例與驗證方法。來源更新使依賴卡片需複核；新環境不自動沿用舊測量。Gotchas 優先來自實際錯誤與核對結果。[How we use skills](https://claude.dev/blog/lessons-from-building-claude-code-how-we-use-skills/)

## I-06｜按需檢索，避免每次讀完同專案經驗

1. 取得本次任務摘要與 task revision，不讀全專案歷史。
2. 範圍、領域、平台與版本先硬篩選；個人經驗仍需符合情境。
3. 回傳最多 6 筆摘要和選用原因，讓 AI 選 ID 詳讀。
4. 以總預算組裝任務脈絡；未讀、被排除和需複核內容分開標明。
5. 需求或來源改變，只重建受影響的脈絡與驗收。重用快取仍驗 task/source revisions。

搜尋初期用正規化欄位＋FTS5、中文切詞及短詞 fallback；向量與跨語言同義詞後置為可選增強。兩者皆須遵守版本及範圍限制；相似度不能當成正確率。

預設摘要約 1,500 estimated tokens、整包約 4,000，並有確定的 bytes 上限；詳讀與附件也有單次限制。task/run 的讀取帳本記錄累計內容量及已送出版本，阻擋無限制翻頁和相同內容重送；擴大預算需說明目的並受設定上限約束。具體契約見 [C-04](references/contracts.md#c-04有界檢索契約)。管理頁可分頁瀏覽全部紀錄，但不把全庫內容回傳給 AI。已進入宿主對話的舊內容，插件不能從其上下文中自行移除。

## I-07｜學習成果如何回報

每次有實質新知或驗證時才建立回報，單純查詢不必生成長報告。機器讀結構化結果，人類讀同一結果的短摘要；詳細案例另按 ID 展開。

```yaml
task_id: task_example
task_revision: 4
outcome: incomplete
knowledge_changes:
  added: [{id: kn_example_01, revision: 1}]
  revised: []
  needs_review: [{id: kn_example_02, revision: 3}]
application:
  level: applied
  evidence_refs: [{id: ev_example_01, revision: 1}]
evaluation:
  baseline: not_measured
  representative: {passed: 2, total: 3}
  held_out: not_measured
  conditions_ref: env_example
remaining_gaps: [最後一個驗收條件未通過]
next_action: 補足缺口後重新驗證
```

上例為資料格式示意，不是本次測得結果。level 表示 retrieved/explained/applied/validated 的可觀察階段；只是「讀過」不得回報已能應用。沒有 baseline 或 held-out 就如實填 not_measured。

重要且重複的任務，才建立對照評估：相同模型/版本、工具、案例、允許時間與成本，分有無知識包；保留沒進入整理流程的新案例作遷移測試。評估版本與題目集合固定，避免把背過答案當成能力提升。獨立 verifier 有條件才用；同模型再讀一次只算第二次檢查，不算獨立證據來源。

衡量指標：必要需求遺漏率、首次成果可接受率、返工次數、重複缺陷率、檢索有用率、來源支撐率、每次取用內容量。每個比率公開分母；使用率或卡片數只是活動量。小樣本與主觀評估明列限制，不製造整體「理解力 95 分」。

## I-08｜方便 AI 編輯、標記與刪除

最小可用工具為 resolve_task_brief、search_knowledge、read_knowledge、propose_knowledge_change、record_evidence、build_learning_report，加上共用方案預檢/套用/還原。工具只公開本次需要的 schema，不按領域複製一整組。

- **編輯**：以 ID＋expectedRevision patch 特定欄位；實質內容改變產生新 revision 並需複核。
- **標記**：可靠程度與保留狀態分開，可標 needs_review、archived、pending_delete，並留下原因/來源/取代關係。
- **整合**：比較卡片條件、獨有主張及反例，保留來源；矛盾未解前不可直接合成一句確定規則。
- **刪除**：先標待刪、查依賴、移入回收區；低使用率只提供整理候選。永久清除與移入回收區是不同動作。
- **還原**：查看指定批次，核對目前版本再恢復；有新修改時提供衝突，不覆蓋。

具體授權已涵蓋方案與前提時直接做，不逐卡重問；授權改變、來源衝突或動作超界才停止。共用協定見 [C-05～C-07](references/contracts.md)。

## I-09｜UI 與人類回饋

獨立導航：**本次任務、知識與經驗、領域來源、成果回報、維護與回收**。共用頂列顯示目前專案、任務與搜尋；MD 工具只以相關文件連結出現。

本次任務主畫面分為目的/限制、未知/假設、選用來源、驗收四區。預設只顯示當前摘要與下一個有影響的缺口。必要問題和建議假設分開，已回答項不反覆詢問。

知識清單先顯示一句摘要、類型、適用條件、狀態與版本；右側詳情才展開正文、證據、反例、修訂歷史。可直接標記、編輯或加入維護批次。來源選用區顯示為何用這筆、為何排除另一筆，讓使用者能修正。

視覺偏好用實際參考 A/B、局部說明與操作狀態表達；保存選擇與用途，不自動成為全領域規則。HTML 原型與 JSON/MD 資料採同一權威來源投影，避免改畫面卻沒更新規格。實際介面以[使用說明](../../README.md)與[實作進度](../../實作進度.md)為準，離線 UI 示意已移除。

## I-10｜模型與平台通用性

| 環境 | 規劃支援與限制 |
|---|---|
| 本機網頁 | 管理資料與查看回報；本身不包含模型，無法自行做所有語意判斷 |
| Codex | 薄 skill＋本機 MCP；在需要時取用資料，沿用宿主授權與工具能力 |
| 其他 MCP 宿主 | 共用資料與工具契約，另測 schema、圖片、結果截斷與分頁；不承諾安裝即全功能相同 |
| 無 MCP 的 AI | 匯出有版本的短脈絡包及來源；修改以差異匯回，無即時工具呼叫 |
| 不同模型 | 以 capability profile 決定文字/圖片及內容預算；弱工具能力可採較小且更明確輸出 |

資料預設儲存在本機；被工具讀給宿主的片段會進入該次 AI 工作脈絡。外部 embedding/模型供應商必須由使用者選用並顯示送出範圍，不能為了語意搜尋預設上傳全部文件。沒有網路或帳號時，保留本機字詞搜尋與手動來源管理。

插件無法自動讀取所有歷史對話、在宿主關閉後持續思考、保證每次自動觸發或修改模型內部知識。排程與多代理需要宿主相應能力與本次授權，不把 Claude 專用命令當成跨平台 API。封裝依 [OpenAI 插件規格](https://developers.openai.com/plugins/build/plugins)。

## I-11｜分期與驗收

| 階段 | 範圍 | 出場條件 |
|---|---|---|
| P0 正確與有界 | 空查詢阻擋、搜尋上限、revision、改內容後需複核、經驗回收 | 舊路徑不能繞過預算；並行修改可偵測；刪除可還原 |
| P1 可理解資料 | 三種卡/證據、領域與環境、FTS、任務脈絡、分頁 UI | 錯版本/錯範圍樣本不回傳；缺口明列；UI 無全量正文 |
| P2 成果與整理 | Thariq 可選方法、實際成果回報、遷移案例、合併維護 | 有證據才稱驗證；缺 baseline 不顯示提升百分比 |
| P3 可攜與強化 | 可選向量、宿主能力適配、匯出匯回、實測比較 | 顯示相容矩陣與評估條件，無能力時能退化 |

測試用隔離、可版本化的任務集，不從使用者全部對話偷偷抽取。必要情境包括：空查詢、中文短詞、相反偏好、不同專案同名物件、版本過時、來源變更、案例未執行、實質修改保留舊證據、兩對話併改、回收還原及上下文上限。v2 尚未實作，以上是驗收計畫。
