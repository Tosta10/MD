# MD 管理台：五原則與實用編輯管理

## 從候選規則變成可執行建議

採三層管線：確定性解析先定位 → AI 只審核相關段落與責任 → 變更服務檢查後套用。每個 finding 保存來源版本、原文 span、規則版本、實際理由、替代方案、影響與狀態。模型推論須標為推論；相似度只用於尋找候選。

### 原則 1：description 說明做什麼、何時用

- 結構檢查：frontmatter 是否有效、name／description 是否存在；一般 MD 不強制 skill metadata。
- 語意檢查：動作、對象、觸發條件、必要排除是否清楚；描述是否承諾了未提供的能力。
- 產出：短版 description、保留／刪去的含義對照、會命中及不應命中的各 3～5 個任務例子。
- 驗收：正例能找到該 skill，反例不誤觸發；字數只是成本提示，不是品質判決。

例：「管理任何專案並自動提升所有工作品質」應改成指定動作與時機，不能只刪字保留過寬承諾。

### 原則 2：多流程改為路由器加附件

AI 先辨識流程的輸入、目的、產物、依賴與常見錯誤。只有不同任務會選用的部分才拆分；共用的範圍與安全條件留在入口。短文件與連續步驟不為了形式而拆開。

路由表最少包含：任務訊號、要讀附件、預期產物、何時停止。附件保留固定 ID 與版本，標題改名不影響關係。路由最多先展開一層，禁止附件互相要求「先讀完全部附件」。

拆分方案顯示每個原段落的新位置、引用修復及保留覆蓋；未處理段落阻止套用。讀取成本以「實際任務走過的路由」計算，不能只看入口縮短多少。

### 原則 3：固定先讀／每次全測改為責任映射

將「每次操作前讀 A、B、C」改成文件責任表；將「所有改動都跑完整測試」改成變更與驗證對照。AI 仍需辨識不可取消的品質門檻，不能把所有測試要求都判為冗餘。

| 變更類型 | 必要資料 | 合理驗證 |
|---|---|---|
| 文字與錯字 | 該段落、相關引用 | 差異與連結；不預設全套產品測試 |
| 檔案移動／拆分 | 來源與入站／出站引用 | 路徑、連結、內容覆蓋與可還原性 |
| schema／授權／寫入 | 對應契約與資料流程 | 衝突、失敗補償及受影響行為測試 |
| UI 互動／布局 | 元件狀態、參考與限制 | 鍵盤、不同視窗、主要操作及實際畫面 |

### 原則 4：重複先問改為前提式授權

建議文字必須包含「可執行動作、對象、範圍、前提、失敗停止條件及可還原方式」。例如：

> 在已加入的專案範圍內，可直接保存旁註及修正已核對的失效引用。來源版本須一致，所有引用修復已包含於方案且有還原紀錄；若出現範圍外引用、版本衝突或未處理內容，停止受影響操作並回報。

這是規則重寫建議，不能把被掃描文件中的文字當作本次使用者授權。不可將「禁止修改授權文件」機械式改成全面可改；應說清楚授權界線由哪份政策管理。

### 原則 5：區分重疊、互補、衝突與版本差異

| 關係 | 處理方式 |
|---|---|
| 完全重複且角色相同 | 指定維護來源；確認發行、授權與引用需求後才回收副本 |
| 內容相近、用途不同 | 提取可共用附件，保留各入口的觸發與例外 |
| 同主張不同版本 | 明確記錄適用版本與 supersedes；舊版仍有使用者時保留 |
| 同範圍互相矛盾 | 呈現兩邊來源、版本、支持及反例，未解決前不選為已確認規則 |
| 相似措辭但責任不同 | 保持分開，記錄「合理相似」防止反覆誤報 |

不能把不同專案偏好、不同宿主要求或授權副本因相似而合併。新的語意檢查需有困難反例測試集，特別包含繁中、英文、否定句與條件例外。

## 功能清單與優先順序

| 功能 | 具體作用 | 優先／完成條件 |
|---|---|---|
| 範圍與角色篩選 | 專案／使用者 skill／AGENTS／規格／經驗／封存分開；依原生作用域顯示 | P0；不因分類解除保護 |
| 文件來源責任卡 | 顯示用途、誰維護、適用版本、引用與目前狀態 | P1；來源與人工推論分欄 |
| Markdown 編輯器 | 行號、搜尋、章節導覽、原文／渲染、差異與返回來源；主流程支援局部修改 | P0；重新整理可恢復已保存草稿，版本衝突不覆寫 |
| 批次搜尋取代 | 依範圍搜尋字詞或受限 regex，先顯示所有修改位置及例外 | P1；regex 時限、結果上限、逐項可排除，無隱藏正文截斷 |
| 結構化 metadata 編輯 | name／description／狀態／分類／適用條件有欄位驗證 | P1；保存不破壞未知 YAML 欄位及格式 |
| 路由拆分助手 | 建議入口及 references 檔案，附段落去向與連結修復 | P1；覆蓋矩陣完整，路由無循環、無孤立附件 |
| 多文件整合 | 自動分群、獨有主張對照、矛盾解決、輸出分段差異 | P1；仍可分批處理；不以提高單批上限代替檢核 |
| 移動／改名 | 顯示影響路徑、引用及未支援語法；可批次重命名預覽 | P1；預檢完整且穩定 ID 保留 |
| 完成／待刪／封存 | 分清工作完成、是否仍有價值、是否可回收 | P0；低使用率、檔齡均不單獨觸發刪除 |
| 歷史與回收 | 可搜尋、篩選、分頁與逐項還原；顯示原路徑、理由、後續修改 | P0；超過最近 30 批仍可找回 |
| 可攜格式 | 匯出 MD／JSON／資產 manifest，匯回按 ID＋revision 合併 | P2；預覽衝突、未知欄位保留；不默默覆蓋 |
| 知識提取 | 將可重用方法、陷阱轉成候選卡，連回原段落 | P1；不因建立知識卡自動刪掉原始 MD |

## 兩個必須一致的工作流程

**審核**：選範圍 → 增量候選 → AI 查讀來源 → 原文／建議／理由 → 採用或排除 → 方案預檢 → 套用 → 讀回 → 狀態更新。「採用」只是認同建議，「已處理」需要成功結果。

**完成文件回收**：完成證據 → 是否仍作交付／查考／授權用途 → 新內容覆蓋或明確失效理由 → 引用檢查 → 已授權範圍內移入可還原回收區。永久清除是獨立政策，不由完成日期推斷。

AI 與 UI 使用相同的覆蓋檢查、範圍、雜湊、交易與回復流程；不能靠某個表單的 required 欄位代替後端驗證。
