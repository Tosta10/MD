# 架構、資料庫與工具契約

狀態：目標架構提案；不修改目前 v2.0.1。保留現有範圍限制、版本檢查、hash、交易日誌及還原能力，逐步拆解集中式實作。

## 1. 模組責任

~~~mermaid
flowchart TB
  H[宿主 AI／其他相容 Agent] --> S[精簡 Skills 與能力描述]
  S --> M[MCP 適配器]
  U[兩個工作台 UI] --> A[HTTP 適配器]
  M --> C[共用應用服務與契約]
  A --> C
  C --> D[文件與五原則分析]
  C --> K[知識與檢索]
  C --> V[視覺與實作證據]
  C --> P[計畫／授權／版本／預算]
  D --> Q[工作佇列與單一寫入協調]
  K --> Q
  V --> Q
  P --> Q
  Q --> DB[(SQLite 結構資料)]
  Q --> FS[原始 MD 與資產儲存]
  K --> IX[可重建全文／向量索引]
~~~

建議從 LegacyWorkbench 的繼承關係拆成組合服務：DocumentService、KnowledgeService、VisualService、RetrievalService、ChangeService、JobService、BudgetService。UI 和 MCP 只做輸入轉換與呈現，不各自重寫業務規則。

AI 做語意分類、理解、解構、產生方案與評價；程式做確定性的查詢、版本、範圍、格式驗證與交易。讓 AI 為每次選取、排序、檔案存取重新推理，反而增加成本與不一致。

## 2. 單一真實來源與資料分工

| 資料 | 真實來源 | 可重建部分 |
|---|---|---|
| 原始 MD | 使用者授權目錄中的檔案及其版本 | 分類索引、段落索引、摘要 |
| 知識／任務／決策 | 有 schema 及版本的資料庫紀錄 | 搜尋索引、向量、MD 匯出 |
| 圖片與影片 | 本機資產檔案＋內容 hash | 縮圖、裁切、關鍵影格、特徵 |
| 驗證結果 | 指向實際產物與環境的證據紀錄 | 報告視圖、統計 |
| 指令與方法 | 明確維護的 skill／AGENTS／方法版本 | 可讀目錄與索引 |
| 操作歷史 | 不可原地改寫的變更事件 | 活動中心彙總 |

不要讓 MD、資料庫和向量庫各保存一份可任意編輯的「最新版」。每種資料只有一個權威來源，其他皆標示為衍生或匯出；匯回時必須比對版本。

建議使用者資料根目錄下設「資料庫」保存 SQLite、資產與索引，與插件安裝程式及 Git 發佈目錄分離。實際位置可由使用者指定；本企畫不建立或搬移現有資料。

## 3. 核心資料模型

採結構化核心欄位＋有版本的擴充 JSON。常用篩選、排序、關聯及生命週期欄位正規化；詳細領域參數可保留 JSON，不為每個新領域改資料表。

| 表／集合 | 主要欄位與責任 |
|---|---|
| projects、scopes | 路徑／資料範圍、所有權、排除、政策版本 |
| tasks、task_revisions | 原始需求、TaskBrief、環境、驗收、變更原因 |
| documents、document_revisions | 穩定 ID、路徑、hash、版本、原始格式 |
| sections、links | 段落定位、標題路徑、引用與依賴 |
| sources、source_versions | 來源、日期、hash、擷取與使用權 |
| knowledge、knowledge_revisions | 類型、命題、條件、例外、有效期、生命週期 |
| knowledge_sources、relations | 依據、替代、矛盾、依賴及路由關係 |
| domains、domain_memberships | 領域包、版本、別名與分類 |
| assets、regions、timelines | 媒體、區域、狀態及時間片段 |
| recipes、implementations | 效果方法、環境、程式／場景版本 |
| evidence、evaluations | 觀察、執行、獨立審核、結果與限制 |
| context_runs、context_items | 任務工作集、讀取版本、選取理由 |
| budget_events | 每次工具與模型呼叫的用量、估計依據 |
| change_plans、operations | 變更前提、差異、條款覆蓋、套用與復原 |
| jobs、job_events | 作業狀態、checkpoint、取消、重試 |
| policies、audit_events | 授權範圍、適用版本、動作與紀錄 |

基本契約：

- 穩定 ID 與 revision 分開；時間用 UTC，顯示時轉成使用者時區。
- provenance、scope、lifecycle、schema_version 不能省略。
- 刪除用墓碑與保留政策表示；索引不得繼續召回已撤回的資料。
- 日期、來源修改與適用版本分開，不用「最後修改時間」代表知識仍正確。
- 版本條件使用結構化比較；無法解析的環境保留 uncertain，不以自由文字猜測成 matched。
- AI 可建立新的領域標籤與資料候選；修改 schema、權限或索引演算法需走軟體版本遷移。

## 4. 資料庫與檢索引擎選型

第一階段維持 SQLite＋全文索引＋資產檔案，先修正候選截取、條件過濾及排序。語意向量以可替換 adapter 加入，不把特定雲服務寫死為核心依賴。

| 規模／需求 | 初始方向 | 升級依據 |
|---|---|---|
| 單機、數千至數萬文件 | SQLite、增量索引、本機資產 | 實際查詢延遲與記憶體 |
| 十萬級以上片段 | 評估本機向量索引與背景工作器 | 召回、更新成本、索引容量 |
| 大量並發／跨裝置共享 | 評估服務型資料庫與向量引擎 | 權限、同步、備份、運維需求 |
| 外部託管檢索 | 可選 adapter | 使用者明確資料出境政策、成本與功能適配 |

資料量只是測試點，不是保證 SQLite 只能到哪個上限。先以 10k 文件、100k 與 1M 片段測試，按延遲、寫入競爭及維護成本決定是否搬遷。關聯圖可先用 SQL 邊表查詢，不預設增加圖形資料庫。

向量是衍生索引，不能作為唯一知識副本。記錄 embedding 模型、版本、維度、切塊規則及來源 hash；更換模型時重建新索引並驗證，再切換，不混合不相容的向量空間。

## 5. 工作、效能與一致性

### 單一寫入協調

兩個插件可透過本機服務協調資料寫入，MCP 連接器維持各自入口。若宿主要求各自 stdio process，仍需共用有 lease 的協調機制，不能依賴每個 process 自己的 Map。

分類＋標記、合併＋引用更新、知識＋來源更新應是明確交易。檔案系統和 SQLite 無法假裝成一個天然原子交易；以預檢、暫存、日誌、套用、提交及補償恢復處理。

### 可恢復工作

作業狀態為 queued、running、cancel_requested、succeeded、partial、failed、cancelled。保存 owner lease、heartbeat、checkpoint、已完成清單、錯誤與重試上限；啟動時辨識中斷作業，安全恢復或要求重新預檢。

可取消代表停止後續工作，不表示已提交的修改從未發生。回復需要獨立操作及版本檢查。

### 增量分析

- MD hash、parser 版本、規則版本共同決定索引有效性。
- rootspecific 分析只處理本次範圍與必要依賴，不先掃完整集合再過濾結果。
- 語法與連結檢查先跑便宜確定性規則；語意審核只送疑似問題及相關上下文。
- 相似度以候選索引縮小比較，長文件須有多區段覆蓋，不能只看前綴。
- 重型解析、向量、影像與跨文件分析交給有界工作器，避免阻塞 UI／MCP。
- 分頁採穩定排序及游標／快照，資料變動時明示是否重新整理，避免漏項與重複。

## 6. AI 與 UI 使用同一份契約

先補齊現有工具缺口：視覺匯入、領域建立／修改、整合覆蓋矩陣、批次標記及可定位段落／連結。不能只在 UI 有功能，卻要求 AI 靠操作網頁才做得到。

候選公開操作群：

| 操作群 | 例子 | 回傳原則 |
|---|---|---|
| discover／query | 列能力、文件、知識、來源、領域 | 分頁摘要、可讀原因、下一步定位 |
| read | 段落、知識欄位、視覺區域／影格 | 受 scope 與共用預算限制 |
| task／context | 建立任務版本、組脈絡包、排除知識 | 保留原需求與推定差異 |
| ingest | 匯入來源、媒體、研究候選 | 校驗、去重、來源紀錄 |
| propose | 編輯、整合、拆分、移動、刪除計畫 | 差異、影響、前提與風險 |
| apply／restore | 套用授權計畫、取消後續、復原 | 版本驗證、交易、可重試結果 |
| evaluate | 保存證據、比較、學習回報 | 區分回報、觀察與獨立驗證 |
| jobs／history | 追蹤、取消、失敗重試、歷史 | 可恢復、可定位操作 |

這不是要求塞成一個接受任意指令的巨型 execute 工具。先把常用工具群精簡到易選用的入口，其他工具依宿主的動態發現能力揭露；不支援時使用受控的靜態工具集合。工具數與 schema 大小應量測，不以「越少越好」代替可用性。

工具輸入通用欄位：scope_id、task_id／revision、run_id、expected_revision／hash、idempotency_key。服務端核對真實政策；模型傳入 policy_id 不能自行取得權限。

工具輸出通用欄位：status、summary、affected_count、items／refs、next_cursor、job_id、revision、budget、warnings、undo_ref。錯誤碼區分無權限、來源變更、預算不足、無結果、部分完成與系統失敗。

高影響修改不能只依 UI 表單阻擋：服務端必須檢查完整來源集合、每個有效條款去向、待解衝突為零、引用及目標路徑有效。覆蓋矩陣漏填一份來源就是未完成，不可通過。

## 7. 預算與可觀測性

BudgetService 接管文件、知識、圖片及工具回應，提供單次與整個 run 的雙層上限。不得在 run_id 缺省時悄悄繞過；服務可發給呼叫者新的 run，但不能偽裝成原工作已無消耗。

估計與實際用量分欄保存。MCP 服務通常看不到宿主全部歷史、推理與計費細節，因此要顯示「插件傳入估計」和「宿主回報實際」兩種來源，不能假稱掌握 Codex 總帳單。

事件可用於診斷延遲、命中率、截斷、索引失效與操作錯誤。預設不把所有原始私密文件複製進日誌；保留 ID、hash 與必要摘要即可。

## 8. 宿主相容及實際可用邊界

Skills 提供方法，MCP 提供資料與操作；兩者分工有利於相容，但不代表任一 AI 網頁都能直接使用。Codex 支援插件組合的能力以其文件和實測為準。[OpenAI Plugins](https://developers.openai.com/plugins/build/plugins)

| 使用環境 | 可用方式 | 限制 |
|---|---|---|
| 支援所需 MCP 能力的 Agent | 呼叫同一資料與操作工具 | 仍須驗證工具、圖片、權限、上下文及平台能力 |
| Codex 桌面 | 安裝 manifest／skills／MCP，開工作台 UI | 不假設可讀所有其他對話或控制宿主計費 |
| 其他具 Skills 機制的工具 | 轉接技能格式及啟動方式 | Skill 發現與優先序可能不同 |
| 無 MCP 的聊天介面 | 手動匯出有限 JSON／MD／圖片包 | 無法自動回寫與動態檢索，使用者需匯入成果 |
| 單獨瀏覽器 UI | 搜尋、編輯、審查、匯出 | 不自動擁有宿主 AI；模型分析需明確連接器 |

目前 Windows PowerShell 啟動設定不能視為跨平台已驗證。未來將平台啟動配置與共用程式分離，針對 Windows、macOS、Linux 逐一驗證。MCP 工具註記也應按實際影響分類，不把產生草稿與永久刪除都標成相同破壞程度。

可選模型連接器另列模型、資料送出範圍、金鑰保存及費用；沒有連接器時把分析工作交給當前宿主 AI，不在 UI 顯示一個其實不能運作的「AI 自動分析」。

## 9. 遷移與回復

1. 記錄目前 schema、資料數、來源 hash 與版本，建立經驗證可還原的備份。
2. 新結構先旁路建立，保留舊資料讀取與 ID 映射；不重設使用者資料庫。
3. 雙路查詢抽樣比較範圍、排序、引用、生命週期及回報結果。
4. 遷移前後驗證筆數、唯一約束、關聯完整性、可定位來源及敏感範圍隔離。
5. 切換新寫入後保留可回復紀錄；若新版寫入不能被舊版理解，使用向前修復或資料匯出，不直接用舊程式開新格式。
6. 索引可重建；原文件、知識版本、驗證證據與授權紀錄不可因升級丟失。

架構重構須與功能分批交付。先統一契約與可觀測性，再拆模組，不為重寫而一次替換全部穩定功能。
