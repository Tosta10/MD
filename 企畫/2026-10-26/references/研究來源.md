# 研究來源、證據與適用限制

查核日期：2026-10-26。外部來源只支持相應的方法與限制，不代表本插件已實作或已取得同樣成效。企畫中的 schema、UI、預算、政策與驗收門檻是本案設計。

## 第一方文件與研究

| ID | 來源 | 本案採用 | 適用限制 |
|---|---|---|---|
| S01 | [Thariq：How We Use Skills](https://claude.dev/blog/lessons-from-building-claude-code-how-we-use-skills/) | 觸發描述、領域陷阱、漸進式載入、資料夾附件 | 不是每個 skill 都必須拆成大量附件 |
| S02 | [Thariq：Finding Your Unknowns](https://claude.com/resources/articles/a-field-guide-to-claude-fable-finding-your-unknowns) | 未知分類、原型、訪談、參考、計畫、決策、說明及驗收問答 | 按任務選用，不固定為每次八步流程 |
| S03 | [Anthropic：Contextual Retrieval](https://www.anthropic.com/research/contextual-retrieval) | 切塊背景、字詞與語意混合、重新排序 | 文中實驗數字不能直接套用本案資料或中文任務 |
| S04 | [Anthropic：Effective Context Engineering for AI Agents](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents) | 高訊號上下文、按需取材、持續整理 | 不能推論規則越少一定越好 |
| S05 | [OpenAI：Retrieval](https://developers.openai.com/api/docs/guides/retrieval) | 語意檢索、來源定位與篩選的能力參考 | 託管服務是選項，不是目前插件既有功能 |
| S06 | [OpenAI：Prompt Caching](https://developers.openai.com/api/docs/guides/prompt-caching) | 快取與上下文長度、費用的差別 | 依模型、供應商與宿主條件，不能保證 Codex 內部策略 |
| S07 | [OpenAI：Images and Vision](https://developers.openai.com/api/docs/guides/images-vision) | 圖像輸入、模型相關成本、細節及空間限制 | 不使用固定每張圖 token 費用估計所有模型 |
| S08 | [OpenAI：Evaluation Best Practices](https://developers.openai.com/api/docs/guides/evaluation-best-practices) | 目標、資料集、指標、比較與持續評測 | 模型自評需校準，不等同獨立客觀證據 |
| S09 | [OpenAI：Build Plugins](https://developers.openai.com/plugins/build/plugins) | Skills／MCP／manifest 的組合與相容設計 | 每種宿主與平台仍需驗證；不假設插件可任意控制宿主 |
| S10 | [Design2Code 論文](https://arxiv.org/abs/2403.03163) | 截圖到程式的元素、布局及人工評測思路 | 前端研究不能直接當作遊戲、動態或美感的普適評分 |
| S11 | [Playwright：Visual Comparisons](https://playwright.dev/docs/test-snapshots) | 對齊環境、基準圖及截圖比較 | 相似度不等於功能、可用性或審美品質 |
| S12 | [W3C：Understanding Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) | 一般文字 4.5:1、大字 3:1 的對比依據 | 色票計算不能替代整頁、多狀態與輔助技術驗證 |

S01、S02 已核對文章內容及作者方法。使用者另提供的訪談摘要、「HTML is the New Markdown」「Thin Prompts, Thick Artifacts, Thin Skills」在本企畫作為設計方向；沒有將未獨立查核的標語、訪談細節或模型成效數字當成直接引述。

本案不依賴「某模型刪掉 80% 指令仍有效」之類數字來推定所有 AI 都適合相同幅度精簡；真正的精簡幅度交由本案評測決定。

## 本機原始碼與歷史證據

分析基準為插件 v2.0.1，commit [30e1254ed4a6174903c72ff0ead6ac2e85e12df7](https://github.com/Tosta10/MD/tree/30e1254ed4a6174903c72ff0ead6ac2e85e12df7)。本次以本機原始碼與既有文件為主，沒有從其他專案或使用者私人資料庫匯入內容。

| 證據類型 | 可以支持 | 不可以支持 |
|---|---|---|
| 程式碼、schema、工具與 UI 契約 | 目前有哪些能力、缺口及潛在邊界 | 所有執行環境都必然重現同一錯誤 |
| 技能入口與附件 | 觸發範圍、路由、重複及分工 | 模型一定會完全遵守 |
| 既有功能測試紀錄 | 當時測試涵蓋的流程 | 本次重新通過、或 AI 品質提升 |
| 既有效能紀錄 | 指定資料／環境的基線 | 新模型、新資料量、媒體處理效能 |
| 本次工具定義 bytes 統計 | schema 規模及重複情況 | 實際模型 tokens、快取命中與帳單 |
| 本次色彩公式計算 | 指定實色組合的理論對比 | 真實 UI 全部狀態都可及 |

具體原始碼位置與差距見 [01 現況架構與差距](../01-現況架構與差距.md)。本次沒有執行實作測試、建置、資料遷移、模型對照或使用者研究；提出的改良應依 [07 驗收方案](../07-Token預算評測與分期.md) 後續確認。

## 研究如何轉成設計

- S01、S02 → 五原則治理、短入口、條件式盲點與原型流程；不是讓來源文章成為新的全域強制指令。
- S03–S05 → 分層檢索與來源入庫；混合檢索效益仍要用本案中文、版本與專案資料測量。
- S06、S07 → 跨工具預算、媒體分層與計費邊界；不假定可控制宿主全部費用。
- S08、S10、S11 → 有基線的任務與視覺評價；最終效果仍需獨立證據及人工校準。
- S09 → 共用服務、宿主適配與資料匯出；不將相容協定誤稱為所有 AI 都自動可用。
- S12 → 藍黑白配色與閱讀基準；美感和流暢性另做任務測試。

所有來源都當作可查核資料。若來源更新或與實作環境不符，應調整方法與適用性，不盲目提高其優先權。
