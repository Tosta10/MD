# MD 管理台與理解工作台：下一階段完整企畫

本企畫最初以唯讀分析建立，現作為v3改造基準。本文保留設計與驗收目標；已實作、驗證及尚待研究的範圍，以儲存庫根目錄的實作進度.md及驗證報告為準。

## 核心決策

保留兩個插件名稱與工作分工，共用一套資料、版本、檢索與變更服務。MD 管理台負責「原始文件如何維護」，理解工作台負責「這次任務需要哪些知識、如何實作及驗證」。AI 負責語意判讀、方案與解釋；確定性的程式負責範圍、版本、交易、索引、預算及還原。

目前產品已能減少重複提供資料、遺漏需求及誤覆寫的風險，尚無對照實驗證明它能顯著提高 AI 的最終品質。下一階段的完成條件必須包含「相同模型在相同成本下是否做得更好」，不能以文件數、卡片數或自評分數代替。

建議優先投資：**可解釋的任務檢索 → AI 與 UI 共用的編輯管理 → 有證據的知識維護 → 視覺實作與驗證閉環**。向量資料庫只是檢索的一環，不作為產品成效本身。

## 產品使用方式

使用者提出目標後，AI 建立或更新本次任務版本，取得與任務、專案和環境一致的少量依據；缺資料時有目的地搜尋。實作後讀回成果與驗證證據，才將有重用價值的內容加入資料庫。一般小修改可以跳過知識檢索和學習歸檔，避免為使用插件而增加流程。

使用者可在介面查看「AI 這次用了什麼、為何選用、哪些仍不確定、消耗多少」，也可直接修改、排除、補充與撤回。知識維護使用事先設定的範圍與動作授權；符合條件即執行，不反覆詢問，並留下可還原紀錄。

## 建議分期

1. **P0 正確性與可觀測性**：共同預算、來源與任務版本、檢索測試集、AI／UI 權限對等、基本編輯與 UX 修正。
2. **P1 實用知識與文件管理**：五原則語意審核、路由拆分、混合檢索、資料入庫與自主維護。
3. **P2 視覺實作閉環**：圖片／區域、動態狀態、效果配方、實作對照、獨立驗證。
4. **P3 規模及相容**：按量測擴充向量索引與儲存、其他宿主適配與評測。

分期以驗收退出，不預先承諾工期或成效百分比。沒有通過品質及成本門檻的模組保持選用或關閉。
