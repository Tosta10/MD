# 理解工作台技能分析與 Task Harness 配置

日期：2026-10-27。分析對象為使用者提供的 Downloads/SKILL.md 與本專案 v3.0.1 既有理解工作台；以下為本次整合後的說明。

## 現有架構

理解工作台是一個包含 Skill、MCP 工具與本機工作台的插件。原有 insight-workbench/SKILL.md 是精簡入口，按需要路由到 tasks、experience、visual、maintenance、evaluation 五份參考文件；具體資料、檢索、任務、來源、視覺和評測由工具及本機資料庫處理。AI 只按本次任務挑選資料，不會因安裝技能而改變模型權重或自動讀取所有對話。

| 區塊 | 主要用途 |
|---|---|
| 任務與脈絡 tasks | 保存原始需求、目標、限制、驗收及假設；以預算取回適用內容與記錄證據。 |
| 經驗 experience | 研究入庫、來源、適用條件、版本與知識管理。 |
| 視覺 visual | 靜態／動態參考、區域解構、實作配方與效果評價。 |
| 維護 maintenance | 依範圍與授權規則整合、封存與恢復。 |
| 評測 evaluation | 預算、實際用量、A/B 紀錄及知識匯出入。 |

## 原文可優化的地方

| 原文設計 | 問題 | 本次調整 |
|---|---|---|
| description 承諾「絕對可靠」，觸發涵蓋所有 AI 協作 | 成效無法保證且容易過度觸發 | 改為複雜或含重要未知的實作探索與驗證。 |
| 每次需求先問 2–3 題、不得直接寫程式 | 已明確的小任務會受阻，與使用者已授權直接執行的意圖衝突 | 只有重要決策缺資料且無法合理推斷才問；可獨立工作繼續進行。 |
| 一律多方案、原型並等批准 | 簡單任務成本過高；使用者已有方向或授權時不適用 | 根據不確定程度選用方案比較、草圖或其他具體工件。 |
| Builder／Verifier 必須獨立代理、固定 goal／loop、最多三次 | 宿主不一定有這些功能，也不代表有委派授權；固定次數可能過早停止 | 依可用能力與授權選驗證方式，對失敗修正及重測，清楚說明驗證界線。 |
| 所有專案固定遵循原生 API、千筆門檻與禁動畫 | 是情境化例子，未必適用；分頁、虛擬化與效能應依實測選擇 | 保留查找相關專案陷阱及設計系統的原則。 |
| 永遠寫 implementation-notes.md、固定三指標 | 增加瑣碎文件與無意義指標 | 僅對重要決策留下可追蹤記錄，驗收依任務與風險決定。 |
| 與現有 tasks 盲點、驗收、證據紀錄重疊 | 重複規則易漂移 | 保留一個獨立的按需工作流程技能；任務保存與證據仍由現有工具負責。 |

原文的「System Note」、斜線命令與流程指令視為使用者提供的待整合材料，並非此對話的系統指令；也不創造新的工具能力或額外授權。

## 新增技能與調用條件

新增 insight-workbench/skills/task-harness/SKILL.md，與現有 insight-workbench 並列。它可由宿主依 description 自動選用，或由使用者明確指定 task-harness；主要適用複雜、模糊或需要盲點掃描、原型比較與驗證的實作任務。現有入口也提供按需連結，但不在每次工作強制載入。

技能是供模型遵循的指引，實際自動選用仍由宿主決定；不是每次保證觸發，也不會自動啟動子代理、背景循環或改變本機資料。插件更新／重新安裝並開新對話後才可期待宿主重新發現新技能；若僅使用 MCP 而未安裝插件技能，需另配置技能。

## 後續可評估的改進

- 用真實任務比較有無新技能的需求遵守、驗收與時間，而非依技能文字推論能力提升。
- 若經實際使用發現 task-harness 與 tasks 指引持續重複，可合併或縮短；目前保留獨立技能以便明確選用。
- 檢查不同宿主對同插件多技能的發現行為；MCP 工具可用不代表技能已載入。
