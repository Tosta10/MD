MD 管理台 × 理解工作台｜使用手冊

版本：v3.0.5。更新：2026-10-26。

開始使用：加入資料夾 → 索引 → 選擇文件／當下任務 → 預覽結果 → 套用或交給 AI。
只開網頁即可人工管理。要讓 AI 讀寫資料，還要在 AI 宿主中連接插件或 MCP。
已有功能與檢索修正的證據；跨模型「AI 變聰明多少」尚未量測。詳見完整測試與成效報告。

1. 先選你要做的事

你的目的使用入口會得到什麼
整理現有／新加入的 MDMD 管理台 → 文件工作區分類、標註、編輯、整合、拆分與復原
檢查 AGENTS／Skill 的五項原則整理待核對有來源的候選與 AI 審核建議
讓 AI 理解這次需求理解工作台 → 本次任務／當下脈絡目的、限制、驗收及少量適用知識
保存搜尋到的方法研究資料庫 → 加入研究資料有版本及來源的研究紀錄
重用已驗證經驗知識與經驗有適用條件、例外與來源的知識卡
解構圖片／動態並記錄實現方法視覺參考區域、影格、時間軸、配方及成果評價
授權 AI 自主整理自治政策明確範圍、動作、額度及復原紀錄
找回操作／未儲存內容操作紀錄／編輯草稿操作結果、持久草稿及衝突提示

2. 三分鐘開始：先開工作台

1. 下載或複製整個 MD 儲存庫；保留兩個插件資料夾、dist 與 public。
2. Windows 雙擊根目錄的「開啟工作台.cmd」開整合介面。也可開各插件內的同名檔案。
3. 到「管理範圍」，加入你明確要管理的完整資料夾路徑。
4. 按「索引新增與變更」，等待完成後再查看文件。
5. 從頁首「使用手冊」或「測試與成效」隨時回到說明。

一般使用已封裝版本不需要 pnpm install。執行需要 Node.js 24 以上；Windows 啟動器也會尋找 Codex 附帶的 Node。直接使用 node 指令接 MCP 時，請先以 node --version 確認版本。

公開來源：Tosta10/MD。

git clone https://github.com/Tosta10/MD.git
cd MD
.\開啟工作台.cmd

若資料夾名稱不同，以實際位置為準。Git、Node、Codex CLI 各是不同工具；不能因能開 Codex 就假設每個命令都已放進 PATH。

3. 怎麼放入既有或新 MD

原始 MD 留在原資料夾，不需要搬進插件資料夾。加入管理範圍後索引即可。

新 MD 位於已加入範圍內時，再按一次索引；未變更正文會重用索引。若要省去手動操作，可在管理範圍啟用監看：它只在服務運行時有效，服務關閉後不會繼續監看。

新檔在範圍外，先明確加入新範圍。個人層級 skills 也需另外加入，不會因管理某個專案就自動讀使用者全部資料夾。

單份 MD 分析上限 2 MiB，非 UTF-8 或無法讀取的來源會回報。受管、授權與硬連結來源保留保護；分類改成「其他」也不會解除保護。

4. 接到 Codex：優先用完整插件

完整插件包含 Skill 方法與 MCP 操作，兩者一起安裝最方便。

此儲存庫已包含 .agents/plugins/marketplace.json，來源名稱為 local-workbenches，畫面顯示「本機工作台」，內含 md-manager 與 insight-workbench。

1. 將儲存庫加入或開成 Codex 的本機專案。
2. 在應用的插件目錄切換到此專案／本機來源。
3. 安裝或更新「MD 管理台」與「理解工作台」。
4. 確認這是支援本機執行的環境；重啟應用或重新連接後，開新對話檢查工具。
5. 請 AI 列出工作台能力及目前已加入範圍，確認真正接通。

若已安裝 Codex CLI，可用官方提供的 marketplace add 加入來源；加入來源仍需在支援的應用中完成安裝。

codex plugin marketplace add "D:\AI\專案\網站\插件"

也可依官方支援的 GitHub 來源格式加入：

codex plugin marketplace add Tosta10/MD --ref main

專案路徑只是本機範例。插件更新後，應用可能仍使用先前已啟動的服務／工具列表；重啟應用及新對話比只重新整理網頁更完整。

只複製 SKILL.md，會得到方法指引，還不等於已連上資料庫工具。只連 MCP，則有操作工具，但其他宿主未必會自動載入這兩份 Skill。

接入方式依據：OpenAI 插件封裝與本機來源。

5. 只接 MCP：Codex CLI 或其他 Agent

本插件使用本機 STDIO MCP。工作台的 http://127.0.0.1 網址是網頁介面，不能當成遠端 MCP Server URL。

以支援 MCP 的宿主設定檔為例，將下列路徑換成實際位置，並確認 command 指向 Node.js 24+：

{
  "mcpServers": {
    "md-manager": {
      "command": "node",
      "args": ["D:/你的資料夾/MD/md-manager/runtime/mcp.mjs", "--role", "md"],
      "env": {
        "CODEX_WORKBENCH_HOME": "D:/MD-Workbench-Data",
        "WORKBENCH_TOOL_PROFILE": "all"
      }
    },
    "insight-workbench": {
      "command": "node",
      "args": ["D:/你的資料夾/MD/insight-workbench/runtime/mcp.mjs", "--role", "insight"],
      "env": {
        "CODEX_WORKBENCH_HOME": "D:/MD-Workbench-Data",
        "WORKBENCH_TOOL_PROFILE": "all"
      }
    }
  }
}

兩個服務使用同一個資料目錄，才會共用資料。可以省略 CODEX_WORKBENCH_HOME，使用預設的使用者目錄；不要一個指向預設、另一個指向新目錄，然後誤以為資料遺失。

上例用完整模式照顧不支援動態工具列表的宿主。支援工具列表變更時，可把 WORKBENCH_TOOL_PROFILE 改成 compact，先載入少量入口，再由 get_workbench_capabilities 取用需要的群組。

各宿主的外層設定格式可能不同。各插件隨附 mcp.portable.json 作為 Node 接入範本；PLUGIN_ROOT 需由宿主解析或手動替換，不能當成真實路徑直接執行。

Codex CLI 的直接連接範例：

codex mcp add md-manager -- node "D:\你的資料夾\MD\md-manager\runtime\mcp.mjs" --role md
codex mcp add insight-workbench -- node "D:\你的資料夾\MD\insight-workbench\runtime\mcp.mjs" --role insight
codex mcp list

完整插件已包含 MCP 時，不要再重複加入同一組直接連接，避免工具重複。此步驟只示範設定，不會由手冊自動修改你的環境。

官方操作：Codex MCP 設定。

6. 哪些模型可以用

判斷單位是「模型能力＋宿主接入＋操作權限」，不是只看品牌名稱。

模型／環境條件可以做限制
能使用工具的文字／程式模型文件管理、知識檢索、來源整理、任務與證據紀錄要由宿主把工具提供給模型
同時支援工具與圖片輸入的多模態模型上述功能，加圖片／影格解構與視覺比較宿主必須轉交 MCP 圖片，不能只回傳圖片 ID
有工具能力的本機小模型可試用分類、查詢及簡單整理複雜語意整合、矛盾與視覺品質需另外評測
無工具能力的聊天模型手動閱讀匯出的資料包及提供建議不能自動操作資料庫或原檔
圖像產生模型作為素材／原型產生環節不能單獨取代管理工具的 Agent
Embedding 模型產生選用語意向量供檢索不是主對話模型；插件不自動呼叫它

GPT、Claude、Gemini、Qwen、DeepSeek 等家族中具備上述能力的型號，都可列為接入候選；不表示每個型號、每個網站版本都已相容。本案目前驗證的是本機 Node／MCP／Windows 啟動與介面，沒有完成各品牌模型的實機矩陣。

使用 Codex 時，可先選目前帳號提供且能調用工具的程式／推理模型。做圖片解構時再確認影像輸入；純文件整理不必為了插件強制選最大模型。模型較強也不能免除來源、範圍及驗收檢查。

一般 ChatGPT 網頁不會讀取你的本機 Codex 設定；把 localhost 網址貼進聊天不等於取得本機工具。此插件沒有遠端 MCP 端點，雲端聊天需要另外受支援的本機執行／正式連接機制。

模型能力與圖片條件：OpenAI 工具指南、圖片理解指南。

7. 接通後先做這個確認

可直接對 AI 說：

請確認 MD 管理台與理解工作台是否已連接：
列出可用能力、版本與已加入範圍，開啟工作台。
這一步只檢查連線，不修改我的文件。

應能得到工作台網址、版本、範圍摘要；需要進階能力時，AI 可以要求 documents、jobs、governance、knowledge、research、tasks 或 visual 群組。

看見工具名稱只證明已發現工具；實際查到範圍、讀回一份測試紀錄，才代表資料連線運作。若工具群組載入後宿主不刷新列表，改成完整模式並重新連線。

8. MD 管理：建議的日常流程

1. 先確認目前範圍及索引狀態。
2. 使用搜尋、狀態與分類縮小文件清單。
3. 點文件名稱閱讀；方框用於選取，不會刪除。
4. 到「整理待核對」查看候選，再由 AI 或人判讀用途與版本。
5. 編輯、合併、拆分或移動時先預覽具體方案。
6. 核對內容及影響後套用；需要回復時到變更批次查看差異與還原。

清單支援每頁 50／100／200 份、前後頁、末頁及直接跳頁。跨頁選取會保留；「取消選取」只取消勾選。

超過 2,000 份時可建立選取快照，最多 50,000 份，再背景分批標記。來源已變更的項目會略過並列為部分完成；不要把「已開始」誤認為全數已套用。

9. 五項原則怎麼使用

原則要核對的事
description是否簡短說明做什麼、何時使用
路由與附件是否真的有多種可分開選用的工作流
固定閱讀／測試能否改成文件責任及按變更驗證
先問再做是否能以既有授權、範圍、前提與停止條件表示
重疊／矛盾是重複、互補、不同版本，還是同條件互相衝突

規則與字詞相似度只找候選。不是字多就必須拆分，不是相似就能刪除，也不是每一條測試要求都該移除。AI 語意審核需有原文、理由與來源版本。

10. 編輯、整合與待刪除

「閱讀」呈現 Markdown；「原始碼」看原文；「編輯」修改內容；「整理工具」提供中繼資料、搜尋取代及路由拆分。

草稿只保存未完成編輯，不表示已改原檔。保存草稿後可重新開啟；來源版本不同時不應直接覆蓋，應比較兩份內容。

整合每批 2–8 份。完整保留的區塊會自動核對；未保留的區塊需逐條填取代文字或捨棄理由。這能防止無紀錄的遺漏，但不能單靠程式證明語意完全等價。

已完成、待刪除與實際回收是不同狀態。標為待刪除先保存理由與依據，實際回收另有方案及引用檢查。此版沒有自動永久清除；封存知識也不會刪掉原始 MD。

11. 理解工作台：不必每次重讀所有經驗

「本次任務」保留原始需求及目標、限制、交付、驗收、未知、假設、環境版本。

「當下脈絡」只選本次適用的少量知識，顯示選用原因、來源、未確認條件及用量。沒有命中時應補充研究，而不是假裝資料庫已有答案。

目前需求修訂或環境改變後，要重新建立符合新版本的工作；舊偏好不能蓋過當下要求。

可對 AI 說：

請把這次需求建立為任務摘要，保留原文。
先列出目標、限制、交付物、驗收與會影響方案的未知。
只檢索目前專案和環境可用的少量經驗，說明選用原因；
不確定的條件另列，實作後再保存有證據的可重用結論。

12. 研究資料庫與知識卡怎麼分

研究資料是有來源的材料；知識卡是從材料及實作提取的可重用命題。

在「研究資料庫」保存標題、網址／定位、作者、使用權、內容摘要、觀察及推論。AI 在宿主中搜尋後也能透過工具存入；插件不會自行爬網。

選擇「提取知識候選」，寫出方法及何時適用。初始保持候選；有驗證依據後才標為可重用。來源更新會讓依賴知識需複查，原有版本與證據仍保留。

不要把對話全文、整本手冊與同一主張的多份重複卡全部塞進常駐入口。常用入口保持短，詳情按需讀取。

13. 視覺：從看圖到如何實現

1. 匯入明確選取的素材，保存來源與用途。
2. 區分看得到的觀察、實現假設及仍無法確定的事。
3. 記錄區域、布局、排版、材質、渲染層及動態狀態。
4. 建立效果配方：技術棧、參數、實作位置、陷阱及驗證方式。
5. 由宿主 AI 在實際專案中實作，再匯入產物或截圖。
6. 對齊環境比較，分別評價功能、布局、可讀性、效能與偏好，留下改善項目。

媒體每份 8 MiB；PNG／JPEG最多 1,600 萬像素。WebP 在介面可轉 PNG。支援編碼且 60 秒內的 MP4／WebM，可由瀏覽器擷取 6 個影格、總覽及時間軸。

「複製 AI 分析任務」會產生貼回已連接 AI 的指令，不會在網頁中偷偷啟動付費模型。圖片必須實際傳給有視覺能力的模型，不能只用文字描述假裝看過。

像素相似度不是美感分數；單圖不能還原隱藏互動，取樣影格也不是完整動畫分析。插件不自動執行外部引擎，實作與測試由宿主工具完成。

14. 自治政策：少問，但有明確範圍

先設定允許範圍、動作、額度、期限、理由及保留期。符合政策且版本、來源、覆蓋及保護條件都通過，AI 才能直接套用；衝突時停止受影響操作。

建議先從「封存明示過期的知識」開始，再按需求增加其他動作。不要用「所有檔案都可以改」代替實際責任範圍。

政策不解除來源保護。失敗嘗試也會占用額度，避免無限重試。保留期目前是紀錄，並不在到期後自動永久刪除。工作台關閉後不會持續自主學習或整理。

15. Token 與資料送到哪裡

一般任務材料目標約 1,500–3,000 額外文字 tokens；預設工作預算是 6,000 估計 tokens、48 KiB 與 3 張圖。它不是整段 Codex 對話的最大用量。

工具定義按需載入；資料先摘要後詳讀，檔案、來源及視覺紀錄有分頁。任務版本、來源版本及索引改變後才重新取材，不靠換 runId 偷繞預算。

圖像與文字都有估計誤差。宿主歷史、推理、輸出、其他工具及費用另計；工具定義少約60.5%不等於總帳單便宜60.5%。

資料庫與資產存在本機。AI 詳讀的片段或圖片會進宿主模型的上下文，是否送雲端由宿主及模型設定決定；「資料庫在本機」不等於全部資料永不離開電腦。

16. 常見問題與排除

情況優先檢查
開網頁後 AI 不會動是否真的安裝 MCP／完整插件；網頁本身沒有內建 AI 連接
看不到新工具是否啟用了所需群組、宿主是否刷新工具列表；必要時完整模式重連
新 MD 沒出現是否在已加入範圍、是否完成索引、是否被忽略或讀取失敗
兩個工作台看到不同資料CODEX_WORKBENCH_HOME 是否一致、是否混用舊版服務
啟動失敗Node 是否24以上、指令路徑是否正確、有無保留整個插件資料夾
合併不給套用來源是否變更、是否有遺漏區塊、取捨文字是否真的存在
圖片／影片處理失敗格式、大小、像素、時長、瀏覽器編碼支援及剩餘預算
知識一直是待複查來源、內容或環境版本是否改變，是否仍缺驗證
沒有資料命中先回報缺口、調整具體問題或補來源，不改成讀完整資料庫
想換回舊版保留新舊資料庫與資產；新版本寫入不會自動合併回舊版
