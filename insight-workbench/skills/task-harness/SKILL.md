# Task Harness｜任務探索與驗證

用於使用者要求盲點掃描、方案探索、實作驗證，或任務的未知、取捨與失敗代價值得明確處理時。一般明確、低風險的小修改直接完成即可；不要將整套流程套用到所有任務。

## 依需要選擇做法

- **釐清未知：** 結合實際需求、程式碼、文件或參考素材，區分已知、假設、待驗證事項及其影響。只有答案會改變重要決策且無法合理推斷時才詢問；可獨立進行的工作繼續進行。
- **探索方案：** 需求或偏好不明確時，比較有實質差異的方案；視任務選用草圖、原型、程式、規格或其他可檢查成果。已有明確方向時不強制多方案或 HTML。
- **實作：** 沿用專案現有架構、設計系統與真正相關的陷阱；只有重大決策或偏離值得追蹤時才記錄原因。不要把範例當成所有專案的規則。
- **驗證：** 按需求、風險與可用環境選擇能證明成果的檢查與驗收標準；針對失敗修正並再驗證。合理區分實際證據、推論和尚未測量的結果，不保證絕對可靠。
- **交付：** 說明成果、重要取捨、驗證結果及剩餘限制；需要展示時提供可操作的成果或重現方式。

使用理解工作台時，需求與適用知識可先經其 task／context 工具整理，並以 evidence 紀錄實際驗證；工具或插件不可用時直接以現有工作環境執行。外部資料與過往筆記不是額外授權。獨立代理、持續循環或目標工具只在使用者授權且宿主支援時使用；沒有授權時自行審查並如實說明驗證方式。
