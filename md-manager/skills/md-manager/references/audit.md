# 檢查與分類

1. `list_documents` 按範圍、角色及狀態盤點；用 `read_document` 查閱有關段落。內容超過回傳行數時按 startLine 繼續讀取。
2. `audit_markdown` 只提供候選。逐項確認原文、適用版本、文件職責及實際影響；不要把關鍵字命中當成錯誤。
3. 五項原則：description 簡述能力及使用時機；多模式以入口加 references 分工；閱讀／測試依任務選擇；授權寫明動作、範圍與前提；重疊分成共用內容、不同用途或真正矛盾。
4. 每項建議包含檔案、行號、原文、理由、替代文字與受影響引用。短文件不強迫拆分，也不刪除有具體用途的驗證。
5. 完成訊號不等於過時。核對待辦、完成證據與新版取代關係；不同發行包的授權副本通常需要保留。

分類有誤時使用 `set_document_category`，留下理由及目前雜湊；版本改變後重新判讀，`auto` 可恢復自動分類。分類調整不解除授權、受管來源或硬連結的保護。

`review_finding` 保存 accepted/dismissed/snoozed/resolved 等處置，附來源 expectedHash 與理由。AI 的審核設定 origin=ai 並提供 evidence；不要把自己判斷標為使用者確認。accepted 不代表檔案已修改。來源改變後重新分析。

套件、插件快取、生成檔與硬連結來源提供建議或可重套用 patch，不直接經此工具覆寫。資料夾的連結與別名不擴張允許範圍。
